## 3 物流知识库工具（logistics_kb_search）技术边界（技术定）

物流知识库对该专家是一个 tool，不是对话本体。Agent 在规划层决定是否调用，调用与否及结果置信度决定后续走引用回答还是兜底。

### 3.1 接口约定

项	定义
入参	query（Agent 改写后的检索式，非用户原话）、filters（business_line=物流，本期写死）
出参	chunks 数组：doc_id、doc_name、chunk_text、score、doc_download_url、archive_time
检索方式	混合检索（向量 + 关键词）+ rerank，由知识库服务内部实现，Agent 侧不感知
调用上限	单轮任务内最多调用 3 次（含改写重试），防止循环检索

### 3.2 置信度与回答策略

检索结果	回答策略
有 chunk 且 top1 score ≥ 阈值	基于知识库内容回答，逐条标注引用（见 8.5）
有 chunk 但 top1 score < 阈值	Agent 改写 query 重试一次；仍低于阈值则按「未命中」处理，不允许拿低分 chunk 硬答
无结果 / 超时 / 服务异常	走 8.4 兜底判定
阈值初始值由算法侧基于测试集标定，配置中心可调；上线前必须过人工标定集，不允许拍脑袋定值。

### 3.3 硬边界（禁止事项）

#	边界
1	知识库未命中时，模型不得用参数知识编造公司内部制度、流程、费率、时效类答案；此类问题只能走兜底文案
2	回答中不得混合「知识库内容」与「模型自有知识」而不加区分；模型补充的通用背景须明确以「一般而言」类措辞标示且不带引用标注
3	知识库内容仅限已归档文档；暂存区未归档内容不进检索范围
4	不回答知识库权限范围外的文档内容（依赖知识库服务侧按调用身份过滤，Agent 不做二次权限判断）

## 4 Web 检索兜底

知识库未命中不等于直接搜网。先分类，再决定兜底路径：
问题类型	判定标准	兜底路径
公司内部类	涉及公司自身流程、费率、时效、系统操作、产品方案（如「我们的结算周期」「平台怎么派单」）	禁止 web search。回复知识检索无结果兜底文案 
行业公开类	政策法规、行业通用概念、公开标准（如「网络货运资质要求」「9% 发票政策依据」）	允许 web search 补充回答

### Web search 约束

#	规则
1	检索词仅限行业与政策层面，禁止拼入客户公司名称、司机个人信息等实体（与销售洞察的 web 检索规则同一标准）
2	Web 来源回答必须前置声明：「以下内容来自公开网络信息，非公司内部制度，实际执行以公司规定为准」
3	Web 结果标注来源站点名，不提供下载，仅提供原文链接
4	政策类回答标注检索日期，提示时效性
5	Web search 单轮最多 1 次调用；检索失败直接走知识检索无结果兜底，不重试

## 5 引用与文档下载

项	规则
引用标注	回答正文中按引用点位角标标注（[1][2]…），消息底部展示引用列表：文档名
引用条数	展示实际支撑回答的文档，去重，最多 5 条；未被引用的召回 chunk 不展示
悬停预览	鼠标移到角标上，弹出卡片显示文档名 + 章节 + 命中原文摘录 + 「定位原文 / 下载」，不打断阅读；点击角标才展开右侧面板做完整定位
右侧文档预览	显示章节定位路径，命中段落黄色高亮，下方给上下文段落。
下载	引用列表每条带下载按钮，下载原始文档（doc_download_url）；下载动作埋点（doc_id + user_id）
失效	文档被知识库删除或重新归档后，历史消息中引用条目保留展示，点击提示「该文档已更新或移除，内容以最新知识库为准」
