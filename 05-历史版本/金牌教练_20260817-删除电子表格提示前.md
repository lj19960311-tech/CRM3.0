## 2 定位与架构判定

### 2.1 一句话定位

你的 AI 销售陪练，帮你练话术、找问题、提能力。它是产品里唯一一个不服务于成单本身、而服务于人的能力增长的场景。

### 2.2 为什么是独立 Agent，而不是主 Agent 下的一个 Skill

金牌教练必须是独立 Agent，且不接受主 Agent 的意图路由。

| # | 理由 | 说明 |
| --- | --- | --- |
| 1 | 人格反转 | 全平台所有 Skill 的系统人格都是「帮销售的助手」；金牌教练的系统人格是「刁难销售的客户」。同一 Agent 内做人格反转会导致人格串味（客户说着说着开始帮销售出主意），这是 roleplay 类场景最典型的失败模式 |
| 2 | 上下文隔离 | 对练上下文里充斥着未经核实的话术试探、销售自己编的数字。这些内容一旦进入主 Agent 的会话上下文，会污染后续的客户分析与方案生成 |
| 3 | 记忆红线 | 主 Agent 的每一次交互都可能写入客户记忆/CRM；陪练内容永不落库到真实客户档案。两套写入策略不能挂在同一个 Agent 上 |


### 2.3 Agent 内部：双角色单会话

金牌教练（coach_agent）内部是两条并行链路共用一个会话，销售每发一轮，同时触发：

扮演链路（roleplay）：以客户身份产出下一轮回复。上下文 = 客户画像 + 本次对练历史。

教练链路（coach_tip）：以教练身份产出一条实时提示。上下文 = 客户画像 + 本轮销售发言 + rubric。

两条链路并行发起，扮演链路是主链路，教练链路是旁路（异步渲染、可失败降级）。

### 2.4 挂载工具

| 工具 | 作用 | 约束 |
| --- | --- | --- |
| persona_load | 加载/组装客户画像（预设、洞察报告、CRM、自建四类来源） | 只取画像结构化字段，不取真实沟通记录原文 |
| case_search | 教练链路引用可验证案例与数字时检索案例库 | 教练提示中出现的任何具体数字必须来自本工具返回，检索无结果时降级为方法论型提示，禁止模型编数 |
| review_score | 复盘评分，按 rubric 逐项判定后由代码算分 | 模型只做逐项判定（是/否/部分），分数由前后端计算，模型不直接给分 |


### 2.5 与主 Agent 的边界

主对话流不路由到金牌教练。销售在工作台问「帮我练一下」，主 Agent 的回复是引导跳转，不是在对话流里开演。

对练过程中销售问产品知识（「我们的准点率到底多少」），直接给兜底文案，让用户去销售秘书里提问。

金牌教练不产生对客材料，不进「我的文件 / 产出物」面板。

## 4 陪练对象（客户画像）

### 4.1 画像字段定义


| 字段 | 必填 | 来源 | 参与扮演 | 说明 |
| --- | --- | --- | --- | --- |
| 客户称呼 | ✅ | 全部 | 是 | 如「王总」，用于对方消息署名 |
| 公司 | ✅ | 全部 | 是 | 如「娃哈哈集团」 |
| 职位 | — | 全部 | 是 | 影响关注点（采购看价、物流看履约、供应链看流程） |
| 业务板块 | ✅ | 全部 | 是 | 单选，取值同 CRM 业务板块：物流服务 / 数智金融 / 商品交易 / AI / 生态营销 / 万联智策 / 电力交易 |
| 产品类型 | ✅ | 全部 | 是 | 多选，选项随业务板块联动（见 §4.3 映射表），决定客户会追问哪一类细节 |
| 决策风格 | —— | 全部 | 是 | 单选：价格敏感 / 关系导向 / 数据导向。扮演语气的主开关。 |
| 企业规模 / 行业 | — | 全部 | 是 | 如「大型钢企 · 年产能约 500 万吨」 |
| 业务特征 | — | 全部 | 是 | 主要货类、运输方式，如「原料公路入厂 + 成品水路公路联运」 |
| 主要顾虑 / 异议点 | — | 全部 | 是 | 异议出招的弹药库，为空时按决策风格走通用异议池 |
| 当前合作阶段 | ✅ | 全部 | 是 | 初次接触 / 观望中 / 需求确认 / 方案报价。决定开场白温度与结束条件 |
| 来源标签 | 自动 | 全部 | 否 | 系统预设 / 洞察报告 · XX / CRM 线索，卡片右上角展示 |
| 一句话画像 | 自动 | 系统生成 | 否 | 卡片描述，由上述字段摘要生成，20–45 字 |


### 4.2 四类来源与规则

| 来源 | 进入方式 | 可删 | 说明 |
| --- | --- | --- | --- |
| 系统预设 | 内置，开箱即有 | ❌ | 一期固定两套：强势压价型（王总 · 娃哈哈 · 采购总监）、谨慎保守型（李经理 · 农夫山泉 · 物流经理）。作为新人第一次进来的兜底，永远不为空态 |
| 洞察报告（830如果完成不了，可以下期再优化） | 自动带入，无需手动导入 | ✅ | 生成过洞察报告的客户自动出现在陪练列表，来源标签「洞察报告 」 |
| CRM 线索（830如果完成不了，可以下期再优化） | 「导入客户」弹窗中手动勾选 | ✅ | 不自动同步全量线索（避免列表被几百条线索淹没）。弹窗内展示：公司、产品、联系人（职位）、获取时间 |
| 自建画像 | 「自建画像」表单 | ✅ | 见 §4.3 |



### 4.3 自建画像表单

布局：第一行三列（客户称呼*、公司*、职位）；第二行三个整宽输入（企业规模/行业、业务特征、主要顾虑/异议点）；下方三组按钮选择（业务板块*、产品类型*、决策风格*）+ 一组（当前合作阶段）。

校验：客户称呼、公司、业务板块、产品类型（≥1）、决策风格 全部填齐后「开始陪练」按钮才由灰变亮；未填齐点击不响应、不弹错误弹窗（按钮态即为提示）。表单下方常驻 带 * 为必选项，其余可留空。

业务板块 → 产品类型联动：切换业务板块时清空已选产品类型（避免脏组合）。映射关系：

| 业务板块 | 产品类型 |
| --- | --- |
| 物流服务 | 承运、易达宝及网络货运、智慧场站、万油通、多式联运、车辆经营、实际承运 |
| 数智金融 | 贷款、票据供应链业务、保险、票据融资撮合业务 |
| 生态营销 | 展示广告、线索广告、GEO、生态套餐产品 |


占位文案：客户称呼「如：王总」/ 公司「如：鞍山钢铁集团」/ 职位「如：物流处处长」/ 企业规模「如：大型钢企 · 年产能 500 万吨」/ 业务特征「如：原料公路入厂 + 成品水路公路联运」/ 主要顾虑「如：价格、切换期断供风险、账期」。

自建画像保存后可复用，与其他来源同列在陪练列表中。

### 4.4 删除

删除走二次确认弹窗：标题 删除陪练客户？，正文 将从陪练列表移除「{客户名} · {公司}」，历史对练记录会保留。

系统预设不可删（卡片不出现删除按钮）。

添加成功 toast：已添加陪练客户「{客户名} · {公司}」，2.4s 自动消失。

### 4.5 画像抽屉（对练中查看）

对练页顶部「客户画像」按钮 / 点击对方头像或名字 → 右侧抽屉展示全部画像字段（label-value 两列）。抽屉内只读，不支持在对练中改画像（改画像等于换对手，必须重开一局）。

## 5 对练场景分类与输出定义

### 5.1 总表

用户在本 Agent 内的动作分为两级：阶段（选客户 / 自建 / 对练 / 复盘 / 历史）× 输入类型。


| 场景 | 触发 | 输出形态 | 复盘入口 |
| --- | --- | --- | --- |
| S1 首次进入 | 侧栏点击，列表非空 | 陪练客户卡片墙（3 列网格）+ 顶部「导入客户 / 自建画像」双按钮 | — |
| S2 洞察报告直达（830要是没有时间做的话，可以先不做） | 报告底部按钮 | 跳过选客户页，直接进对练，顶栏展示正在扮演：{姓名} · {公司}{职位} + 来源标签 | 右上「结束对练」 |
| S3 开场 | 选定客户/自建完成 | 客户先开口，按画像输出开场白（见 §5.2）；不显示任何欢迎语式系统消息 | — |
| S4 常规对练轮次 | 销售发言 | ① 客户回复（左气泡）② 教练实时提示（💡 卡片，紧跟销售气泡之后） | — |
| S5 销售跑题 / 试探出戏 | 见 §8 | 客户角色不出戏；教练层给出方向纠正 | — |
| S6 销售零发言直接结束 | 点「结束对练」且发言 0 轮 | 不生成复盘，直接回列表，toast 还没开口，先说两句再复盘吧 | — |
| S7 主动结束 | 点「结束对练」且发言 ≥1 轮 | 复盘卡直接嵌在会话流末尾（不跳页），下方出现「再练一次 / 返回客户列表 / 返回工作台」 | ✅ |
| S8 达到轮数上限 | 销售发言满 30 轮 | 系统灰条 本次对练已达 30 轮，先复盘一下 → 自动生成复盘 | ✅ |
| S9 历史回放 | 历史抽屉点击某条会话 | 只读模式，输入框隐藏，顶栏展示历史回放 · {时间}；已复盘的连复盘卡一起回放 | 底部「返回列表 / 和 TA 再练一次」 |


### 5.2 开场规则

客户先开口，销售不需要想第一句怎么起头（降低启动成本）。

开场白由 决策风格 × 合作阶段 决定，长度 ≤50 字，必须包含一个压力点（时间紧 / 已有供应商 / 已有竞对入围 / 只谈价格），不允许出现「有什么可以帮您」这类助手腔。

三种决策风格的开场基调：

| 决策风格 | 基调 | 示例 |
| --- | --- | --- |
| 价格敏感 | 强势、压时间、直奔价格 | 说吧，这次又想推什么？我只有十分钟，价格没有优势就别浪费我时间。 |
| 关系导向 | 客气但不给承诺，先看人 | 坐吧。咱们也算朋友介绍认识的，先聊聊，合不合作另说。 |
| 数据导向 | 冷、要指标、拒绝形容词 | 资料我看过了。直接讲重点，拿数据说话。 |


### 5.3 客户扮演输出规范

| 项 | 规则 |
| --- | --- |
| 长度 | 单轮 ≤120 字；一轮最多抛 2 个问题（超过就成了审讯，练不动） |
| 语气 | 严格贴合决策风格；允许不满意、允许打断、允许拒绝，但不做人身攻击、不涉及性别地域等冒犯内容 |
| 对话顺序 | 优先消费画像里的「主要顾虑」字段，逐条抛出；顾虑用尽后按合作阶段推进（要证据 → 要承诺 → 要下一步） |
| 让步条件 | 销售给出可验证证据或明确承诺才让步一档；纯形容词（「我们服务很好」）不推进剧情，客户复读追问 |
| 收尾 | 客户方在满足让步条件 3 次后给出软性 close（约下次、要材料、要标书），但不出现「那我就签了」这类失真结局 |
| 不出戏 | 任何情况下不承认自己是 AI、不跳出角色解释规则（解释交给教练层） |


### 5.4 实时教练提示（💡）规则

| 项 | 规则 |
| --- | --- |
| 触发 | 销售每发一轮后触发一次，渲染在销售气泡下方 |
| 样式 | 💡 图标 + 你的 AI 教练： 加粗前缀 + 提示正文 |
| 长度 | ≤80 字，必须包含一句可直接照着说的示范话术（引号内），不做纯评价 |
| 类型 | ① 补数字型（对方在试探底气 → 给可验证区间）② 补证据型（引可比案例）③ 转承诺型（口头保证 → 写进 SLA/合同）④ 锁下一步型（时间、材料、参与人） |
| 数字红线 | 提示中出现的任何具体数字（降本比例、准点率、赔付标准）必须来自 case_search 返回；检索无结果时降级为方法论表述（「给出可验证的区间并说明来源」），严禁模型自造数字——销售会把提示里的数字直接带去见客户 |
| 防刷屏 | 同一类型提示连续出现 2 次后，第 3 次必须升级为完整示范话术（整段可复制），不再重复同类建议 |
| 降级 | 教练链路超时（>3s）或失败：静默跳过本轮提示，不报错、不阻塞客户回复；本轮不计入复盘的逐轮点评 |


## 6 复盘报告

### 6.1 生成条件

| 销售发言轮数 | 输出 |
| --- | --- |
| 0 轮 | 不生成（见 S6） |
| 1–2 轮 | 生成复盘，但不出评分条，只出「做得好的 / 可改进点 / 逐轮点评」，并在评分区位置提示 发言轮数太少，这次不打分。练满 3 轮以上我才能给出有参考价值的评分。 |
| ≥3 轮 | 完整复盘（评分 + 定性 ） |


### 6.2 结构


复盘卡自上而下：

头部：📋 图标 + 标题「对练复盘」+ 副文案 你共发言 {n} 轮 · 本次对练已连同复盘存入「历史对练」

画像标签行：企业规模、合作阶段、画像标签依次平铺（提醒销售这份评价是在什么设定下得出的）

表现总结：四维度评分条（横向进度条 + 右侧分值）

✅ 做得好的（至少2 条，最多5条）/ 🔧 可改进点（最少2条，最多5条）左右分栏

动作区：再练一次 / 换一个客户 / 返回工作台

### 6.3 评分 rubric（四维度）

打分方式：模型只做逐项判定（达成 / 部分 / 未达成 = 25 / 12 / 0 分），四项相加得该维度分值，分数由代码计算。模型不允许直接输出总分。 这样同一段对话重复评分结果稳定，且每一分都能追溯到具体检查项——后续做人工标定集时可以直接复用这套 rubric。

| 维度 | 检查项（各 25 分） |
| --- | --- |
| 开场与破冰 | ① 是否在首轮点到对方业务痛点 ② 是否避免无信息寒暄堆砌 ③ 是否说明来意与预计占用时长 ④ 是否匹配对方决策风格的沟通节奏 |
| 需求挖掘 | ① 是否问到量化信息（运量/线路/账期/现承运商）② 是否用确认代替假设 ③ 提问与陈述比例是否健康（提问 ≥30%）④ 是否挖到画像之外的新信息 |
| 异议处理 | ① 是否正面回应而非绕开 ② 是否给出可验证证据 ③ 是否把风险转化为可承诺条款（SLA/赔付/试点）④ 是否在同一异议上被追问超过两次仍未解决（触发则本项 0 分） |
| 价值传递 | ① 是否用数字或案例而非形容词 ② 是否对齐对方 KPI（成本/时效/合规/担责）③ 是否说明可比性 ④ 是否在结束前锁定明确下一步（时间、材料、参与人） |

## 8 兜底策略

| 场景 | 处理 |
| --- | --- |
| 陪练列表为空 | 不可能出现（系统预设不可删）。若异常为空：还没有陪练对象，先导入一个客户或自建一个画像 + 双按钮 |
| 销售试探出戏（「你是 AI 吧」「别演了直接告诉我答案」） | 客户角色不出戏，按画像回一句符合人设的敷衍（如「你说什么？我没听明白」）；教练层同轮提示 这是模拟，请按照对练模式回复。回到刚才那句「{对方上轮问题}」，试着正面接一下。 |
| 连续 3 轮试探出戏 | 教练层接管一次，灰条系统消息 要查产品资料或问知识，回工作台找物流产品专家更快。这里我们练怎么说。 并提供「返回工作台」按钮，对练仍可继续 |
| 销售在对练中问产品知识（「我们准点率多少」） | 客户不回答（不是客户该知道的）；教练提示 这个数据回工作台问物流产品专家，拿到准确口径再回来练。 |
| 销售编造承诺（「我们保证 100% 不出问题」） | 客户顺势追击（「写进合同吗？做不到赔多少？」），教练同轮提示纠正口径 |

## 9 数据与隐私红线

对练内容永不写入真实客户档案——不写客户记忆、不写客户笔记、不同步 CRM、不进入洞察报告的数据源。陪练是练习场，不是数据源。

不使用真实沟通记录原文扮演。画像只取结构化字段（规模、货类、顾虑、风格），不把 CRM 里的真实聊天记录、拜访纪要喂给扮演链路。

复盘仅本人可见

教练提示与复盘中的具体数字必须可溯源（case_search 返回），无来源时降级为方法论表述。

页面常驻底部声明：AI 生成内容仅供参考，重要决策请结合实际情况判断；对练顶栏常驻 模拟场景，不会写进真实客户记录。
