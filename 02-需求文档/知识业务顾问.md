## 3 物流知识库工具（logistics_kb_search）技术边界（技术定）

物流知识库对该专家是一个 tool，不是对话本体。Agent 在规划层决定是否调用，调用与否及结果置信度决定后续走引用回答还是兜底。

### 3.1 接口约定

| 项 | 定义 |
|---|---|
| 入参 | query（Agent 改写后的检索式，非用户原话）、filters（business_line=物流，本期写死） |
| 出参 | chunks 数组：doc_id、doc_name、chunk_text、score、doc_download_url、archive_time |
| 检索方式 | 混合检索（向量 + 关键词）+ rerank，由知识库服务内部实现，Agent 侧不感知 |
| 调用上限 | 单轮任务内最多调用 3 次（含改写重试），防止循环检索 |

### 3.2 置信判断维度

算法需要综合以下维度计算置信分，并输出可支持产品决策的高、中、低置信状态。各维度的具体计算和权重由算法侧确定。

| 维度 | 作用 |
|---|---|
| 意图匹配 | 判断问题最终任务与生态营销、物流、金融领域等的匹配程度 |
| 检索相关性 | 判断检索内容是否能够直接支撑用户问题 |
| 时效性 | 当前有效资料优先；过期资料不作为回答 |
| 适用范围 | 产品、业务、用户角色和流程阶段是否匹配 |
| 证据一致性 | 多份可靠资料是否支持同一结论 |
| 冲突惩罚 | 不同资料存在互斥口径时降低置信度 |

阈值初始值由算法侧基于测试集标定，配置中心可调；上线前必须过人工标定集，不允许拍脑袋定值。

### 3.3 检索结果与回答策略

用于处理单个知识库或单次知识检索的结果；多个知识库同时命中时，按第四章的跨领域路由规则处理。

| 检索结果 | 回答策略 |
|---|---|
| 有 chunk 且 top1 score ≥ 可回答阈值 | 基于知识库内容回答，逐条标注引用（见第 6 章） |
| 有 chunk 但 top1 score < 可回答阈值 | Agent 改写 query 重试一次；仍低于阈值则按“未命中”处理，不允许使用低分 chunk 硬答 |
| 无结果 / 超时 / 服务异常 | 按“未命中”处理，不使用低置信候选生成答案 |

### 3.4 回答安全边界（禁止事件）

| # | 边界 |
|---|---|
| 1 | 知识库未命中时，模型不得使用参数知识编造公司内部制度、流程、费率、时效类答案；此类问题只能使用兜底文案 |
| 2 | 回答中不得混合“知识库内容”与“模型自有知识”而不加区分；模型补充的通用背景须明确使用“一般而言”等措辞标示，且不添加知识库引用标注 |
| 3 | 知识库内容仅限已归档文档；暂存区未归档内容不进入检索范围 |
| 4 | 不回答用户权限范围外的文档内容；由知识库服务根据调用身份完成权限过滤，Agent 不进行二次权限判断 |

## 4 与物流、财务、生态知识的跨领域路由

系统根据用户是否显式 @ 专家确定检索范围，再按照统一置信判断规则生成答案。

| 场景 | 检索范围 | 回答策略 |
|---|---|---|
| ① 用户已 @ 专家库 | 仅在用户指定的专家知识库内召回；例如 @生态营销业务专家 时，仅检索生态营销知识库 | 基于该专家库中达到可回答阈值的内容生成答案并标注引用，不再调用未被指定的专家库 |
| ② 用户未 @ 专家库 | 对生态营销、物流、金融等全部可用知识库进行搜索召回 | 对全库候选统一评分、语义去重，选择达到可回答阈值且置信分最高的结果生成一套主答案并标注引用 |

两种场景共用以下判定规则：

| 路由状态 | 判定条件 | 输出策略 |
|---|---|---|
| 唯一高置信候选 | Top1 ≥ τ 且 Top1 - Top2 ≥ δ | 选择 Top1 所属知识库作为主路由，仅基于该候选生成答案并标注引用 |
| 跨领域歧义 | Top1 ≥ τ 且 Top1 - Top2 < δ | 暂不生成答案，提出一个区分领域或任务意图的澄清问题；用户补充后重新检索、评分和路由 |
| 无可靠候选 | Top1 < τ | 按“未命中”处理，不使用低置信候选生成答案 |
| 语义重复候选 | 多个知识库命中相同或高度相似的知识内容 | 先进行语义去重，再按统一置信分保留最优候选，避免重复输出 |

其中，Top1、Top2 为跨知识库候选经统一评分后的第一名和第二名，τ 为可回答阈值，δ 为候选区分度阈值。统一评分采用第 3.2 节的置信判断维度；各知识库未经校准的原始检索分数不得直接比较。最终仅输出一套主答案，不拼接多个知识库的候选答案。τ、δ 的具体取值及评分实现由算法侧确定。

场景示例：

| 项目 | 示例一：已 @ 专家库 | 示例二：未 @ 专家库 |
|---|---|---|
| 用户提问 | @生态营销业务专家：在线营销产品适合哪些客户？ | 哪个生态服务套餐适合有运输营销需求的客户？ |
| 检索范围 | 仅检索生态营销知识库 | 检索生态营销、物流、金融等全部可用知识库 |
| 召回结果 | 生态营销知识库命中“在线营销产品适用客户”，统一评分为 0.88 | 生态营销知识库命中“生态服务智选套餐适用场景”，统一评分为 0.86；物流知识库命中“运输服务适用条件”，统一评分为 0.72 |
| 路由判定 | 候选达到可回答阈值 | Top1 = 0.86，且与 Top2 的分差达到候选区分度阈值 |
| 最终处理 | 仅基于生态营销知识库生成答案并标注引用，不调用物流或金融知识库 | 选择生态营销知识库作为主路由，生成一套答案并标注引用，不同时输出物流知识库答案 |

注：示例分数仅用于说明，实际阈值由算法侧确定。

## 5 Web 检索兜底

知识库未命中不等于直接搜网。先分类，再决定兜底路径：

| 问题类型 | 判定标准 | 兜底路径 |
|---|---|---|
| 公司内部类 | 涉及公司自身流程、费率、时效、系统操作或产品方案，如“我们的结算周期”“平台怎么派单” | 禁止 Web Search，回复知识检索无结果兜底文案 |
| 行业公开类 | 政策法规、行业通用概念或公开标准，如“网络货运资质要求”“9% 发票政策依据” | 允许使用 Web Search 补充回答 |

### 5.1 Web Search 约束

| # | 规则 |
|---|---|
| 1 | 检索词仅限行业与政策层面，禁止拼入客户公司名称、司机个人信息等实体，与销售洞察和物业务顾问的 Web 检索规则采用同一标准 |
| 2 | Web 来源回答必须前置声明：“以下内容来自公开网络信息，非公司内部制度，实际执行以公司规定为准” |
| 3 | Web 结果标注来源站点名，不提供下载，仅提供原文链接 |
| 4 | 政策类回答标注检索日期，并提示信息可能随政策调整而变化 |
| 5 | Web Search 单轮最多调用 1 次；检索失败后直接使用知识检索无结果兜底文案，不重试 |

## 6 引用与文档下载

| 项 | 规则 |
|---|---|
| 引用标注 | 回答正文中按引用点位角标标注（[1][2]…），消息底部展示引用列表：文档名 |
| 引用条数 | 展示实际支撑回答的文档，去重，最多 5 条；未被引用的召回 chunk 不展示 |
| 悬停预览 | 鼠标移到角标上，弹出卡片显示文档名 + 章节 + 命中原文摘录 + 「定位原文 / 下载」，不打断阅读；点击角标才展开右侧面板做完整定位 |
| 右侧文档预览 | 显示章节定位路径，命中段落黄色高亮，下方给上下文段落。 |
| 下载 | 引用列表每条带下载按钮，下载原始文档（doc_download_url）；下载动作埋点（doc_id + user_id） |
| 失效 | 文档被知识库删除或重新归档后，历史消息中引用条目保留展示，点击提示「该文档已更新或移除，内容以最新知识库为准」 |
