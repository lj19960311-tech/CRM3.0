# 三.  关键业务规则

## 3.1 客户画像

|**模式**|**触发条件**|**工具顺序**|**主对话输出**|
|---|---|---|---|
|询问“企业产品、效益计算、洞察报告相关|只问产品、产品组合、产品方案、推荐产品、效益计算、销售洞察、洞察报告、|企业地图 → 三查一宝|仅展示客户名称、经营状态、经营范围、统一社会信用代码、法定代表人、注册资本、实缴资本、注册时间、注册省市、参保人数、主要类型|
|询问“客户信息”相关|单独询问企业信息/画像|企业地图工商/高管/风险/招投标 → 三查一宝  → 线索信息表  → websites 按固定来源顺序检索近 90 天信息|主对话展示工商底档、线索归属和掉落情况（没有则为空）、高管信息（建议对接人）、核心业务（物流需求）、经营阶段和合作建议摘要；高管、发展历程、证据及完整分析进入独立报告|

**强制规则：**

- 客户画像顺序固定为 `企业地图 → 三查一宝 → websites`，不得提前、并行或跳过前置工具。

- 【询问“客户信息”相关】：websites 必须执行近 90 天动态、招投标和舆情任务，不受产品场景“内部无数据才联网”限制，但不得覆盖工商底档信息。

- websites 只补充公开信息，不得补写内部合作历史、内部计算效益、私人联系人、线索归属或掉落状态。

- 线索信息：每条至少包含线索ID、产品类型、线索状态、归属销售、掉落状态、掉落时间/原因（如有）、更新时间和线索来源。

- “是否掉落”只能读取线索表的明确状态或掉落标记，不得模型判断推断；字段缺失时展示“ - ”。

- 同一企业多条线索不得按企业名称合并；归属销售发生变更时展示当前归属。

- 企业深度报告必须：覆盖集团高管（拜访对接人）、核心业务与产品（物流需求推断）、发展历程（扩张/转型/稳定/收缩/亏损判断）、合作建议、综合总结；无可靠姓名或经营证据时返回目标岗位或“证据不足”，不得补造。

### 3.1.1  websites 固定来源优先级

|**顺序**|网站类型|主要用途|使用要求|
|---|---|---|---|

|2|政府及官方登记、公示平台|工商、行政许可、处罚、环保、项目备案、产能信息|法定事实优先；保留发布单位和发布日期|
|3|上市公司公告、证券交易所、|高管、财务、产能、投资、亏损、扩张和重大项目|经营阶段和亏损判断的最高优先公开证据|
|4|政府采购、公共资源交易、招投标平台|运输招标、原料采购、车辆、仓储、物流项目和建设项目|保留报名/截止时间和项目状态和项目类型|
|5|中国信用网、法院、执行、信用、税务、环保等官方公开渠道|被执行、失信、诉讼、欠税、处罚和整改|企业的风险信息的主要来源|
|6|行业协会、产业园区、政府新闻稿|行业地位、产业链、基地、扩产和产业政策|与企业官方或公告交叉验证，主要以官网公告为准|
|7|权威财经与行业媒体|近期经营动态和市场背景|国家级央媒直属财经>国家级媒体旗下专业财经垂直媒体 >头部市场化权威财经媒体>普通行业垂直媒体 / 财经资讯平台如：新华社>上海证券报>每日经济新闻>雪球|

### 3.1.1  各信息中数据来源优先级

|**信息**|主来源|次级来源|禁止事项|
|---|---|---|---|
|工商底档|企业地图中的工商/官方数据|三查一宝、政府登记页面|不用联网获取的数据覆盖法定字段|
|线索归属与掉落|CRM 线索信息表|无公开替代来源|不用网页、久未跟进或销售变更推断掉落；不展示越权记录|
|集团高管|企业地图 → 三查一宝 → 官网管理团队|年报/公告 → 政府新闻 → 权威媒体|不凭姓名搜索结果推断任职|
|核心业务与产品|官网产品/业务栏目|年报、招股书、政府项目资料|不要把行业常识写成该公司事实|
|发展历程|官网历史、年报和公告|政府/园区材料、权威媒体|无时间和来源的事件不进入正式时间线|

|拜访对接人|企业地图/三查一宝中的人员名称和职务、有来源的姓名、职位和职责|无公开数据|不生成私人联系方式；无姓名时只建议岗位，没有数据时，不展示|

## 3.2 客户案例与行业通用方案

|**能力**|**数据源**|**匹配条件**|**无结果处理**|
|---|---|---|---|
|客户案例|相似案例库|行业类型、细分类型、产品|明确无匹配；不得编造客户、数字或成效|
|行业通用方案|通用解决方案库|行业类型、细分类型|明确无匹配；不得用案例或模型生成内容冒充已审核方案|

- 两者是独立意图、独立 Skill、独立 Tool Call 和独立结果区。

- 只查询其中一项时，不得调用另一项；用户明确同时需要，或销售洞察计划包含两项时，分别建立两个步骤。

- 案例和行业解决必须来自授权案例库和通用解决方案；公开网页不得包装成内部案例。

- 两类资料均需独立鉴权，并支持在线预览和下载。

## 3.3 默认值与 HITL

所有需要用户选择、填写、调整或确认的字段必须提供**默认值及数据来源**。

> 默认值优先级：
> 
> 1. 当前用户已确认值。
> 
> 2. 当前客户有效画像或业务系统数据。
> 
> 3. 同一用户对同一客户的最近确认值。
> 
> 4. 版本化行业或产品默认值。
> 
> 5. AI 推荐值。
> 
> 

**需要确认的值：**

|**确认点**|**触发条件**|**未确认时**|
|---|---|---|
|客户主体|多主体|不继续查询和生成|
|画像与因子计算参数|进入产品匹配或完整测算前|任务停在等待确认|
|第 1/2、2/2 轮计算问题|参数问题数超过 10|保留进度，不跨轮|

## 3.4 因子参数分轮与报告（与目前系统逻辑保持一致）

|**问题数**|**确认方式**|**报告**|
|---|---|---|
|`≤ 10`|单轮确认|确认后生成完整报告|
|`> 10`|固定第 1/2、2/2 两轮|第一轮后生成阶段报告，点击“进一步洞察”之后 第二轮后重算并生成完整报告|

- 生成文件名： `{客户名称}_物流综合解决方案.pdf`和 `{客户名称}_企业深度洞察报告.pdf`；

- 生成文件之后可以直接在右侧弹出进行预览，第一次不需要用户点击打开。后续用户在右侧关闭之后，在点击打开在右侧预览。

## 3.5 记忆

- 自动记录用户确认的事项、产物。

- 生成的报告和产品附件和相似案例和通用解决方案都存在“我的文件”中。

# 四. Skill 定义与 Tool边界

> Agent 对最终目标、总体计划、跨步骤状态和完成条件负责；Skill 只完成被分配的子目标；Tool 负责确定性查询、计算、生成、记录或发送。模型不得绕过 Skill 、工具顺序、权限或 HITL。
> 
> 

## 4.1 唤起方式

|**方式**|**规则**|
|---|---|
|显式唤起|用户从首页点击物流产品专家/专家技能页点击能力入口或输入框 `@物流产品专家` 进入。|
|意图路由|主对话出现推荐产品、产品需求、客户画像、企业信息、产品组合、收益测算、客户案例、行业通用方案等单一相关意图时，规划层自动路由至物流产品专家能力域。用户无感知，不展示“已切换专家”等提示；置信度不足时只问 1 个最小澄清问题。|
|多意图|同一消息命中两个及以上意图，尤其产品意图与客户信息、线索归属、案例或行业方案同时出现时，不得直接单一分发，也不得立即并行调用 Tool，需要先进行澄清。例如“帮我查一下【娃哈哈】公司的相关案例和目前归属谁”，需要先让用户明确明确意图，不能同时输出。|

## 4.2 能力边界

|#|边界|
|---|---|
|1|只处理客户画像、产品推荐、销售洞察、效益计算、客户案例、行业通用方案、报告。物流履约、开票结算、合同定价、授信审批等不在本专家范围，不调用无关 Tool。|
|2|涉及具体企业时，先企业地图，再三查一宝；单独询问客户信息时，再只读查询 CRM 线索表，并按规则调用 websites。主体未确认前不进入后续查询、推荐或报告；不得跳过、并行或调整顺序。|
|3|询问客户信息时，websites 必须检索近 90 天动态、招投标和舆情；询问产品、组合、方案或推荐产品时不得联网。联网仅补公开信息，不覆盖工商底档，不补写内部合作、效益、私人联系人、线索归属或掉落。|
|4|产品及场景只能来自物流产品与场景库。模型不得新增、修改、推断库外产品或场景，也不得绕过不适用规则；库中无结果时明确告知未找到。|
|5|效益及所有可量化结果只能由收益因子模型计算。模型只传参和解释，不心算、不改写、不补造；画像和因子参数未确认时不得输出正式测算或完整方案。|
|6|CRM/线索表仅在主体确认且权限通过后只读查询。归属销售和掉落只取明确字段，缺失显示“-”；不得根据未跟进、销售变更或网页推断，不新增或修改线索状态，不生成私人联系方式。|
|7|相似案例与行业通用方案必须分别来自相似案例库和通用解决方案库，作为独立意图、Skill、Tool Call 和结果区。单项查询不得调用另一库或用网页/模型兜底；无结果不编造，预览下载需鉴权。|
|8|同一消息命中两个及以上意图时必须先澄清，让用户明确当前要处理的一个意图。确认前不得单一分发、并行调用 Tool 或同时输出多个结果。|
|9|所有需要用户选择、填写、调整或确认的字段必须提供默认值及来源。客户主体、类型和场景/因子参数和分轮问题未确认时停在等待确认，不得使用未确认值继续执行。|
|10|计算问题 ≤10 时单轮确认；>10 时固定两轮。第一轮后仅生成阶段报告，用户点击“进一步洞察”并完成第二轮后才重算并生成完整报告。|

## 4.3 Tool范围

|Tool|核心范围与限制|
|---|---|
|企业地图|主体、基础工商、风险、关键人、关联企业、招投标和动态；画像必须先调用|
|三查一宝|工商补充；企业地图  后调用|
|websites|公开官网、政府、交易平台和权威媒体、上市公司公告等|
|物流产品与场景库|产品能力、适用场景和组合规则、场景的解决方案；仅能使用库里面的产品，禁止大模型修改与推理|
|收益因子模型|效益的计算逻辑、单位；模型仅传参与解释，无结果禁止补写|
|相似案例库|已经有的案例、案例的成效、和附件；无结果禁止补写|
|通用解决方案库|已经有的行业解决方案和附件；无结果禁止补写|
|CRM/线索信息表|按已确认主体查询授权客户、全部线索、当前归属销售、明确掉落状态|
|文档生成器|用批准模板生成PDF；不得自行补事实|
|文件服务|预览、下载、收藏和短时链接；每次访问重新鉴权|
|邮件服务|与企业微信打通，仅发给登录系统账号人员的邮箱|
