## 三. Skill 定义与唤起边界

> Skill 负责意图理解、查询条件补全、工具编排和结果组织；Tool 负责根据结构化参数查询数据库。Skill 不直接访问数据库，Tool 不理解开放式自然语言；两者均不具备联网搜索和业务写入能力。
> 
> 

### 3.1 唤起方式

|方式|路由说明|
|---|---|
|显式唤起|用户在首页点击“线索管家”卡片、在专家技能页点击该能力，或在输入框中选择 `@线索管家`。|
|意图路由|主对话中出现“线索归谁”“当前负责人”“归属时间”“线索状态”“是否掉落”“掉落时间”“掉落原因”等查询意图时，自动路由到本 Skill，不展示“已切换专家”类提示。|
|多意图|一条消息包含多个线索查询问题时，可拆分后依次或并行查询。例如，用户问“北京启明科技这条线索现在归谁，是什么状态，是否已经掉落”，本 Skill 分别查询归属、状态和掉落信息，再合并为一个回答。若同时包含其他业务意图，例如“查一下北京启明科技的线索归属，再帮我生成一份营销方案”，必须走澄清选择，本 Skill 只处理线索归属查询。|

### 3.2 能力边界

|#|边界|
|---|---|
|1|只回答当前用户有权限访问的内部数据库数据，不访问互联网、搜索引擎、外部网页或第三方公开数据。|
|2|只展示数据库已有的线索基本信息、当前归属、归属记录、掉落记录和线索状态，不生成数据库中不存在的业务结论。销售预测、客户画像以及其他非线索查询业务不在本 Skill 范围，交由主 Agent 或对应业务能力处理。|
|3|数据库查不到相关线索或字段时，明确返回“未查询到相关数据”，不得使用模型知识、行业常识或上下文猜测补全。|
|4|当前 Skill 全程只读：不创建申请，不发起审批，不更新负责人、线索状态、掉落状态或任何其他业务字段。|
|5|只能访问当前用户有权限查看的组织范围和字段；无权数据不得通过汇总、推断、关联信息或错误提示间接泄露。|
|6|查询结果必须标明数据时间。数据缺失、数据过期或查询服务不可用时，返回“数据不足”或“暂时无法查询”。|
|7|只有在询问线索掉落规则的时候，才能follow up问，同省/跨省的线索|

### 3.3 Skill 与 Tool 分工

定义 **1 个 Skill 和 3 个只读 Tool**：

|类型|名称|职责|
|---|---|---|
|Skill|`lead_assignment_query`（线索归属与掉落查询）|识别客户名称（即线索名称）、产品类型，理解线索归属、掉落结果和线索状态相关的查询意图，选择 Tool 并组织回答。|
|Tool|`lead_search`（线索基本信息查询）|定位线索，返回 `lead_id`、产品类型、来源、创建信息、当前状态和数据时间|
|Tool|`ownership_search`（线索归属查询）|根据 `lead_id` 返回当前负责人、所属团队、归属时间等|
|Tool|`drop_record_search`（线索掉落查询）|根据 `lead_id` 返回掉落状态、实际或预计掉落时间、数据库已有原因和数据时间|
|Tool|`drop_case_get`（固定掉落案例读取）|按案例类型返回预置内容；当前仅有2个固定案例：1个同省案例、1个跨省案例|

## 四. 交互设计

### 4.1 查询与澄清

|输入|处理|
|---|---|
|有客户名称|查询具体线索；产品类型用于缩小范围|
|有销售名称|查询该销售名下的线索列表|
|缺少定位条件|文本追问客户名称、销售名称或线索编号或产品类型|
|页面或会话已有唯一线索|沿用 `lead_id`，不重复追问|
|销售重名|输出所有的销售信息包括所在公司信息|
|多条候选线索|按照【线索更新时间】倒序，展示全部候选结果|
|线索掉落规则|必须选择业务板块、产品类型、线索来源之后，才能返回结果|
|线索掉落原因|查询具体线索掉落原因和掉落时间|
|数据更新时间及来源|数据更新时间：取CRM线索最新更新时间，如果线索已掉落，则取掉落时间；来源：数据的真实来源|
|followup questions|根据用户query 生成推荐问题，点击后，可以直接发送|

### 4.2 结果渲染

|结果类型|前端组件||字段/操作|
|---|---|---|---|
|销售重名|表格||选择框（多选）、序号、销售名称、销售邮箱、所属公司（一级公司/二级公司）|
|单条线索|表格||输出：客户名称、产品类型、线索ID、归属销售、所属公司、线索状态、掉落风险等级📢 其中线索状态和归属销售和掉落风险等级高亮显示|
|多条线索|表格||① 输入：【客户名称】有多少线索时：输出：序号、客户名称、产品类型、线索ID、归属销售、所属公司、线索状态、掉落风险等级、操作（查看掉落信息）② 输入：【张三】有多少线索时：输出：序号、客户名称、产品类型、线索ID、线索状态、掉落风险等级、操作（查看掉落信息）📢 其中线索状态和归属销售和掉落风险等级高亮显示|
|销售名下线索|表格||序号、客户名称、产品类型、线索ID、所属公司、线索状态，掉落风险等级、操作（查看掉落信息）|
|线索掉落规则|筛选框+文本||筛选业务板块、产品类型、线索来源之后，返回具体规则、计算公式和注意事项。可进行`【同省/跨省的案例】`追问。|
|单条线索掉落原因|文本+时间轴||① 返回线索的基本信息、掉落原因、掉落时间、从创建线索到掉落时间/当前时间的时间轴、后续处理意见② 掉落状态为【未掉落和已掉落】的时候才会有时间轴。|
|线索掉到怎么办|文本||① 固定文本{{`【解决方案】：``1.线索掉落后可在公海及时认领哦，本省公司销售2天内不可认领哦！``2.若在公海查询不到，可能被其他销售已认领，可在【线索归属查询】查看线索当前的归属人】`}}② follow up ：线索的掉落规则、查询【某某线索 】归属人|
|线索掉落风险|文本+跳转链接|① 固定文本（里面的数字会根据具体的线索发生变化）：{{**查询结论**您目前持有线索：0条，目前触发掉落预警的线索 0条，其中掉落风险：● 二级风险 0条 ● 一级风险 0条**解决方案**请到万联易达CRM小程序-工作台-我的线索中，及时查看具体线索的掉落时间和掉落原因吧，二级掉落风险的线索更要抓紧处理哦！！！跳转链接：https://wlyk-dev.10000da.vip/system/cluemanage/list】}}② 链接只有小程序时使用时才显示，跳转到`小程序-工作台`。|

## 五. 需要用到的数据 - 取值 CRM 

1、业务板块、产品类型、线索来源，所有值以及对应的编码

以及不同业务板块对应的配置，未转商机天数、未跟进天数、未认证天数、未成交天数、再次成交天数、是否启用，掉落人是否再次认领

2、线索ID，客户名称，产品类型，归属销售（id+名字+邮件），所属公司（一级公司和二级公司），线索状态（已认证/业务沟通/..），跟进状态（未跟进/未成交/..）以及对应的配置天数，同省份销售累计持有天数，线索创建人，创建时间，获取线索人，获取时间，上次掉落时间，目前掉落状态，掉落日期，掉落原因，风险等级（一级/二级），线索的更新时间。
